# RULES — Zenoot App

## Rules kerja (wajib dibaca tiap sesi baru)

- Selalu baca dan pahami struktur kode dari file ZIP yang dikirim sebelum mulai apapun
- Trace properly — jangan tebak-tebak, harus trace flow secara menyeluruh sebelum menyimpulkan root cause
- Tidak bolak-balik — fix harus benar dari awal, bukan reaktif trial-error
- Sebelum eksekusi apapun: unzip & trace struktur kode dulu (bukan tebak dari nama file/fungsi)
- Kalau nemu potential root cause yang levelnya keputusan desain besar (bukan sekadar bug kecil), presentasikan dulu opsi-opsi + konsekuensinya, baru eksekusi setelah dikonfirmasi
- Tiap kode divalidasi sebelum dikirim: node --check (syntax), hitung brace {}/() balance, cek div-depth di innerHTML template literal harus balik ke 0
- Kalau nemu kode/behavior yang kelihatannya bug tapi ternyata sengaja (ada komentar penjelasan sebelumnya), jangan main ubah — jelasin dulu root cause & alasan desain lamanya
- **DILARANG ada dead code (aturan diganti 8 Okt 2026)**: fungsi/field/variabel/markup/CSS yang jadi tidak terpakai gara-gara perubahan HARUS DIHAPUS saat itu juga, bukan dibiarkan atau dikomentari. Satu data = satu acuan. Sebelum hapus, grep dulu semua pemakainya supaya tidak ada yang putus. (Dead code lama yang masih tersisa dari era aturan sebelumnya baru dibersihkan kalau user minta sapu bersih.)
- Perubahan skema database (ALTER TABLE) gak bisa dieksekusi otomatis — kasih SQL persis, tunggu konfirmasi dijalanin baru lanjut kode yang gantung ke kolom itu
- Setiap kirim file hasil edit, selalu sertakan instruksi deploy yang jelas

**analisis.html — NET INCOME TOKO jadi satu-satunya acuan (8 Okt 2026)**: Setting field `minNpmRp` ("Minimum Profit Toko") DIHAPUS, diganti `netIncomeToko` ("NET INCOME TOKO", Rp per pcs, per toko). Konsep: Net Income = Profit + Operasional, jadi Ops saling meniadakan dan TIDAK ikut di penyebut rumus harga: `NET (Harga Minimum) = (HPP + BPP + Net Income Toko) ÷ (1 − Admin − ACOS − Buffer)` di `calcNetPrice` (dipakai Price List, By Operasional, By Target Qty, By Harga Jual) dan `byhargaCompute`. By Harga Jual: MASUK/TIDAK MASUK = Net Income aktual ≥ Net Income Toko (`c.netIncome`, `c.diff`, `c.ruang`, `c.roasMin`); Profit/pcs (`c.income`) tinggal rincian (= Net Income − Operasional), ROAS impas = Profit 0. Kartu atas "Net Income / Pcs"; kartu "Net Income Toko" tinggal 4 baris (target, aktual, selisih, hasil); "Posisi harga kamu" (`byhPosisi`) ikut membandingkan Net Income. By Operasional & By Target Qty: NET Income = Net Income Toko × order, NPM = Net Income − Operasional (dulu NPM = Min Profit × order lalu + Ops); label "PROFIT TRGT" → "NET INCOME TRGT", "RASIO PROFIT" → "RASIO NET INCOME". Saran RKS (`rekapGuide`, poin 4) membandingkan Net Income per pesanan = (NPM + Operasional) ÷ pesanan dengan Net Income Toko; cabang "masalah operasional" dihapus karena Ops sudah termasuk Net Income. Pesan error "ADMIN+ACOS+LAINNYA+OPS" jadi tanpa OPS. Variabel mati `incomeHarian` (By Target Qty) dihapus. **PENTING**: nilai lama Minimum Profit tiap toko TIDAK dikonversi (bergantung harga) — isi ulang Net Income Toko per toko di Setting; sebelum diisi (0) Harga Minimum = (HPP+BPP) ÷ (1−Admin−ACOS−Buffer) dan semua harga di atasnya dianggap MASUK.
